# AetherRSI Protocol v0.1

Status: draft. The core in this repository is the reference implementation; `conformance/` decides pass or fail.

An extension is **one folder with an `aether.json` manifest**. The core reads manifests only. It never imports extension code:
pages run in sandboxed iframes and agents run as separate processes.

## 1. Manifest

```json
{ "aether": "0.1", "kind": "preview", "id": "md-preview", "label": "📝 Markdown", "match": [".md"], "entry": "index.html" }
```

| Field | Kinds | Rule |
|:--|:--|:--|
| `aether` | all | Protocol version. In 0.x the minor must equal the core's. From 1.0: same major, minor not newer than the core |
| `kind` | all | `preview`, `agent` or `app` |
| `id` | all | `[a-z0-9][a-z0-9-]{0,39}`. First one found wins; later duplicates are reported and skipped |
| `label` | all | What the UI shows |
| `entry` | preview, app | A file inside the folder (relative, no `..`) |
| `match` | preview | File extensions, e.g. `[".md", ".markdown"]` |
| `command` | agent | argv list. `{dir}` = the extension folder, `{python}` = the core's Python |
| `inject` | agent | `true` if the agent accepts more text while running (default false) |
| `guard` | agent | `true` if the agent honours `protect` (§4). A locked core does not run agents without it |
| `agent_rules` | app | A file inside the folder with instructions for the agent (e.g. `CLAUDE.md`) |

Unknown fields are ignored. A folder whose manifest breaks a rule is skipped and listed in `/api/info` `errors`.

## 2. Where extensions live

| Kind | Found in |
|:--|:--|
| preview, agent | `<workspace>/extensions/<folder>/` and `<data>/extensions/<folder>/` (data defaults to `~/.aether-rsi`) |
| app | any folder of the workspace's file tree |

Install = `git clone` into one of these folders. Uninstall = delete the folder. The core rescans when the folder changes.

## 3. Pages (preview and app)

The core loads `entry` in `<iframe sandbox="allow-scripts">` and serves it with `Content-Security-Policy: sandbox allow-scripts`.
The page therefore has an opaque origin: it cannot call the core's API, read cookies or reach the parent DOM.
Previews are served from `x/<id>/`, apps from `files/<path>/`.
Because the origin is opaque, the page's own requests carry no cookies, so behind an authenticating proxy they would fail.
The core therefore delivers an HTML page as **one document**: relative `<script src>`, `<link rel="stylesheet">` and `<img src>` inside
the folder are inlined, and `<script src="aether-sdk.js"></script>` becomes the SDK. Anything else (data, other files) is read with `read`.

Messages are `postMessage` objects `{aether: "0.1", type, ...}`. The core accepts messages only from the frame it opened.

| Direction | type | Fields | Meaning |
|:--|:--|:--|:--|
| core → page | `open` | `path`, `name`, `text` (preview) or `folder: true` (app), `error?` | What to show. Sent after load |
| core → page | `rev` | `rev` | Something changed in the core (a job moved, a task changed) |
| core → page | `dest` | `task` (`{id, title}` or null) | The task the composer is addressed to |
| core → page | `theme` | `dark` | Colour scheme of the shell |
| core → page | `reply` | `id`, `ok`, `text` or `error` | Answer to `read` |
| page → core | `quote.add` | `label`, `text` | Add a quote chip to the composer. The person sends it |
| page → core | `send` | `text` | Put text in the composer. **Not sent**: sending is always the person's click |
| page → core | `task.open` | `id` | Open a task's conversation |
| page → core | `read` | `id`, `path` | Apps only: read a text file inside the app's own folder |

## 4. Agents

The core starts `command` with the workspace as the working directory, one process per job, in its own process group.
Both directions are **JSON lines** (one object per line, UTF-8).

core → agent (stdin):

```json
{"type": "start", "aether": "0.1", "prompt": "…", "session": "id or null", "cwd": "/abs/workspace", "protect": ["/abs/core", "/abs/data"]}
{"type": "inject", "text": "…"}
```

agent → core (stdout):

```json
{"step": "📖 README.md"}
{"session": "id"}
{"done": true, "reply": "…", "cost": 0.012}
{"error": "…"}
```

- `prompt` is the message followed by its quotes (`@n label` and `> text`); an app quote asks the agent to read its `agent_rules` first.
- `session` is whatever the agent reported last time for the same task, so a task is one conversation.
- `inject` arrives only if the manifest says `inject: true`. The core closes stdin after `done`; text arriving later becomes the next job of the same task.
- `protect` lists folders the agent must not write to (empty when the core is unlocked). Agents declare `guard: true` to say they enforce it.
- Stop = the core sends SIGTERM (then SIGKILL) to the process group.
- Exit without `done`, or any `error` → the job fails with that message (or the tail of stderr).

## 5. Core HTTP API (for the shell; extensions do not call it)

All URLs are relative, so the core also works under a proxy prefix. POST requires the header `X-Aether: 1` and rejects `Origin: null`.
See the docstring of `aether/server.py` for the list of endpoints.

## 6. Lock

By default the core is locked: the file tree and file reads stay inside the workspace and never enter the core or data folders,
and agents receive those folders in `protect`. `<data>/config.json` with `{"core_locked": false}` unlocks it; the shell then shows 🔓.

## 7. Not in v0.1

`serve` (a backend process per extension behind `x/<id>/`, HTTP and WebSocket) is planned for v0.2.
